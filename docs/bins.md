# Bins

Generated by `bun run docs` from each bin's `--help` description, do not edit.

## audit

the known vulnerabilities of the Bun repositories under root (the current folder by default), one table per repository. Package `workspace`.

Instead of: a bun audit run in each repository and a read of every advisory to find what is worth fixing

```sh
audit [options] [root]
audit
audit ~/Workspace --level high --prod
```

## base

runs a command at HEAD or another ref in a temporary worktree, the working tree untouched. Package `base`.

Instead of: git stash, a test run, then git stash pop

```sh
base <command> [options]
base -- bun test tests/api.test.ts  # the test at HEAD, the working tree changes left out
base proof -- bun test tests/new.test.ts  # it fails at HEAD and passes in the working tree
```

## changelog

generate the release notes and publish them. Package `changelog`.

Instead of: writing the release notes by hand and posting them through the Forgejo UI

```sh
changelog <command> [options]
changelog --dry-run  # the notes since the last tag, nothing published
changelog undo v1.2.0 --dry-run  # what undoing that release would remove
```

## check

runs the repo's check, typecheck, lint and test steps, from package.json scripts (through bun run), composer.json, a Justfile or a Makefile, and for PHP from phpstan.neon (typecheck), .php-cs-fixer.dist.php (lint, dry-run) and phpunit.xml.dist (test) when composer.json has no such script. Package `check`.

Instead of: chaining docker compose exec <service> bun run check | tail, lint and test by hand, or bun run check && bun run lint && bun run test read through tail

```sh
check [--only <steps>] [--changed] [--failed] [--timeout <duration>] [--slot] [--in <service> | --host] [--list]
check
check --only lint,test  # two of the steps
check --in app  # every step inside the app service
```

## cli

the bins of the @kaynooo/cli-* packages, described by their own help. Package `doctor`.

Instead of: running each bin's --help to find the one that fits

```sh
cli <command> [options]
cli list
cli list --json  # with each bin's synopsis and examples
```

## db

read-only SQL against Postgres, MySQL and MariaDB, credentials never shown, writes only on a _test database. Package `db`.

Instead of: psql or mysql with the connection string on the command line, docker exec <container> psql -U ...

```sh
db <command> [options]
db "select count(*) from users"
db -c booki-db-1 "select count(*) from users"  # a container outside the compose project
db describe users  # the columns, indexes and foreign keys of a table
db search email  # where a field lives
db explain "select * from users where email = 'a'"  # the plan, nothing executed
```

## dc

runs docker compose on the stack found here: the nearest compose file or .env setting COMPOSE_FILE up to the repository root, else the only stack with containers here. Package `docker`.

Instead of: docker compose -f docker-compose.prod.yaml --env-file .env.prod, typed again for each stack

```sh
dc [project] <compose args>
dc up -d
dc dash logs -f  # a stack that came up from other files
```

## dev

small developer utilities: passwords and bcrypt hashes, JWTs, timestamps, UUIDs, base64, URLs and file hashes. Package `dev`.

Instead of: openssl rand, htpasswd, jwt.io, date -d, uuidgen, base64, sha256sum and one-off scripts for each

```sh
dev <command> [options]
dev password
dev jwt <token>  # header, payload and expiry
dev ts 1700000000  # an epoch as dates
```

## dlog

one line per compose service with its state and health, then the last distinct error lines of the services that log some or are not healthy, repeats collapsed to one line with a count and secrets masked as redact does. Package `docker`.

Instead of: docker compose ps, logs --tail | grep -i error and docker inspect for health

```sh
dlog [service...]
dlog
dlog php db  # only those services
dlog -n 10 --since 15m  # ten error lines of the last quarter of an hour
dlog --level warn  # warnings too
dlog --grep "timeout|5\d\d"  # the lines matching a regex
dlog --fail-on down --fail-on unhealthy  # a gate that ignores old errors
dlog --json  # the report as JSON
```

## doctor

checks this host's @kaynooo/cli-* install, one line per check, the command that fixes a failing one beside it, and installs the packages it picks. Package `doctor`.

Instead of: checking each bin's version, tea's login and the hooks by hand

```sh
doctor [--only <check>] [--quiet] [--fix | --install [<name>...|all]] [--list] [--dry-run] [--force] [--json]
doctor
doctor --json  # the checks for a script
doctor -q  # silent unless something fails
doctor --fix --dry-run  # what --fix would run
doctor --install  # check to install, uncheck to remove
doctor --install forgejo check hooks  # three named ones
doctor --install all --dry-run  # what installing everything would run
```

## dx

without a terminal (a script, a pipe, an agent) `dx` lists the services with their state, ports and image: that listing is the form to use there, `--json` giving the full record. On a terminal it picks one instead: enter opens its shell (or brings a stopped service up), ctrl-l follows its logs, ctrl-r restarts, ctrl-x stops and ctrl-b rebuilds it. The services last acted on come first, per folder. Package `docker`.

Instead of: docker compose exec <service> bash, logs -f and restart typed per service

```sh
dx [service] [action]
dx
dx php  # a shell in php, or php brought up when stopped
dx php logs  # follow its logs
dx php logs --tail 50 --no-follow  # the last 50 lines, then exit
dx -  # the last action again
```

## errs

prints one `file:line:col: message (rule)` line per error found in a tsc, tsgo, vue-tsc, bun check, eslint, keslint, bun test, vitest, playwright (list and line reporters), phpunit, paratest, phpstan (table, raw and json), php-cs-fixer, go (build, vet), cargo (rustc), ruff (concise and full) or pytest log, read from the file given, from stdin (no argument or -), or from the output of the command run after --. Package `check`.

Instead of: reading raw tsc, eslint, phpunit, phpstan or playwright logs, or grepping a test summary out of them

```sh
errs [options] [log]
errs -- bun run check  # the type errors of a run
bun test 2>&1 | errs  # the failed tests from stdin
errs -- vendor/bin/phpunit  # each failed PHP test with its file and line
```

## ev

.env files listed and edited with secrets masked. Package `env`.

Instead of: cat .env, grep on env files and editing them by hand

```sh
ev <command> [options]
ev list
ev get DATABASE_URL  # one key, its value masked
```

## fix

alias of `check --fix`. Runs the folder's fixers: the project's own `fix` script, else its `lint:fix` and `format` ones (package.json through bun run, composer.json, a Justfile or a Makefile), then the formatters its files call for: php-cs-fixer where configured and composer.json has no fixer, just --fmt, go fmt and go mod tidy, cargo fmt, ruff where configured, and every Makefile target declared .PHONY. Package `check`.

Instead of: running each fixer and formatter by hand, or docker compose exec <service> bun run lint:fix

```sh
fix [--only <fixers>] [--timeout <duration>] [--in <service> | --host] [--list]
fix
fix --list  # the fixers it would run
```

## ft

Forgejo tools over tea, run from a repository whose origin is on Forgejo. Package `ft`.

Instead of: tea api calls piped through jq, and sleep loops waiting on CI

```sh
ft <command> [options]
ft ci  # wait for the runs of origin's tip, failures printed
ft issue 12 -c  # an issue with its boxes numbered and its comments
```

## gb

without a branch, picks one when a terminal is attached: the branches last checked out first, as the reflog has them, then the other local ones, then the remote ones with no local branch yet. The header says where HEAD stands, each row how its branch stands against its upstream and whether it is merged into the base. enter switches to it (a remote one gets its local tracking branch), ctrl-n creates a branch named after the query, ctrl-d deletes the highlighted local branch with `git branch -d`, which refuses one not merged yet, and ctrl-r fetches, prunes and lists again. Without a terminal it lists the branches instead. Package `git`.

Instead of: git switch, git branch -d and git checkout typed per branch

```sh
gb [branch]
gb
gb feature  # switch to feature, or create it from origin/feature
gb -  # back to the previous branch
gb -c fix/login  # create a branch and switch to it
gb -d old  # delete a merged local branch
```

## gc

commits exactly the paths given, its message checked before anything is staged. Package `git`.

Instead of: git add, git status and git commit chained

```sh
gc <title> [-m <line>]... [--ticket <line>]... -- <path>...
gc "fix(api): retry a timed-out fetch" -- src/api.ts
gc "feat(ui): a dark theme" -m "The toggle sits in the header." --ticket "#12 - Dark theme" -- src/theme.ts src/header.ts  # a body line and a ticket
```

## gl

GitLab pipelines over glab, run from a repository whose remote is on GitLab. Package `gitlab`.

Instead of: glab ci and glab api .../pipelines/<id>/jobs polled in a sleep loop

```sh
gl <command> [options]
gl ci  # wait for the pipeline of origin's tip, failed tests printed
gl logs 1234 -j test  # one job's failed tests
```

## gst

the repository's branch, upstream, changed files and HEAD in one line, then the changed paths by staged, unstaged and untracked. Package `git`.

Instead of: git status --short and git log --oneline

```sh
gst [--log N]
gst
gst --log 5  # with the last five commits
```

## guard

the safety rules a Claude Code Bash call is held to, each refusal naming the route. Package `guard`.

Instead of: a hook script per rule, each wording its own refusal

```sh
guard <command> [options]
guard check "git push --force"  # the rules a command breaks, with their routes
guard path .env  # whether a file tool may open a path
```

## hotspots

ranks the source files under dir (here by default) by complexity times churn, the ones both hard to read and often edited first, honouring .gitignore. Package `code`.

Instead of: guessing which files are worth splitting first

```sh
hotspots [options] [dir]
hotspots
hotspots src --since "3 months ago" --limit 10
```

## j

without a name, picks a recipe, target, script or task of this folder, its parents and its child folders when a terminal is attached, and runs it. The ones run last come first, per folder. Without a terminal it lists them instead. Package `check`.

Instead of: reading the Justfile, Makefile, package.json scripts or composer scripts to find what to run, then retyping it

```sh
j [name] [args...]
j
j test  # run the test recipe, script or task
j api/test --watch  # a child folder's, with an argument
j just:check  # the one of a runner, when several share the name
j -  # the last one again
```

## out

runs the command and shortens its output when it is long, exiting with its code. Package `out`.

Instead of: piping a noisy command through tail or head

```sh
out [-n <lines>] -- <command> [args...]
out -- bun install
out -n 300 -- bun run build  # up to 300 lines left untouched
bun run build 2>&1 | out  # what is piped in
out --stats --since 7d  # the tokens saved this week
```

## peek

prints files or line spans with their line numbers, several in one call. Package `code`.

Instead of: sed -n N,Mp, grep -n chains and whole-file reads

```sh
peek [options] <file[:from-to]>...
peek src/a.ts:120-140 src/b.ts:1-40  # two spans in one call
peek --def parseArgs src  # a whole declaration
```

## pick

a fuzzy selector, the lines on stdin in, the chosen one on stdout out. Package `pick`.

Instead of: fzf for a quick choice in a pipe, select in a shell script

```sh
pick [options]
git branch --format='%(refname:short)' | pick
ls | pick --multi --preview 'head -20 {}'
```

## pid

shows what a process is: its executable, working directory, command line, parent chain up to init, user, start time and age, memory, open files and limits, the TCP and UDP ports it listens on and its cgroup. Everything is read from /proc; what the calling user cannot read of another user's process is left out and named at the end. Package `proc`.

Instead of: cat /proc/<pid>/{cmdline,environ,limits}, readlink /proc/<pid>/{exe,cwd}, the fish pid function

```sh
pid <pid>
pid 4242  # executable, directory, command, parents, memory, limits and ports
pid 4242 --env  # with the environment, secrets masked
pid 4242 --json
```

## pkg

checks npm packages before they are added, and moves a lib's consumers onto a new release. Package `pkg`.

Instead of: bun add on trust, and a bun info and sleep loop then a bun add per consumer

```sh
pkg <command> [options]
pkg zod  # the name, the newest version two weeks old, its licence and scripts
pkg bump @kaynooo/cli-kit --dry-run  # the consumers a release would move
```

## ports

lists what listens on this machine, TCP and UDP over IPv4 and IPv6, one row per port with its bound address, the owning process, its command and its working directory. A port Docker publishes is held by docker-proxy, and shows as its compose project and service when docker is installed; the owner of a socket of another user cannot be read and shows as -. Package `proc`.

Instead of: ss -ltnp | grep, lsof -i, fuser -k and lookups of docker-proxy by hand

```sh
ports [port]
ports  # every listening port with its owner
ports 3000  # who holds 3000, exit 1 when nobody does
ports 3000 --kill --yes  # stop it
ports --json
```

## probe

reports each site's negotiated HTTP version, redirect chain, timings, addresses, TLS and certificate, the headers worth knowing and what warrants a warning. Package `probe`.

Instead of: the httpversion fish function, curl -sI chains and openssl s_client one-liners

```sh
probe [options] <url|domain>...
probe example.com
probe https://example.com/path --json
probe a.test b.test  # one line each
probe https://example.com --resolve example.com:203.0.113.7 -H "Host: example.com" --verbose  # a server before its DNS points at it
```

## proc

what a process is, who listens on a port and which dev processes are worth cleaning, read from /proc. Package `proc`.

Instead of: cat /proc/<pid>/..., ss -ltnp, lsof -i and pgrep -f one-liners

```sh
proc <command> [options]
proc pid 1234
proc ports
proc procs  # the leftover or heavy processes, dry-run first
```

## procs

lists the leftover or heavy processes of the calling user that are worth cleaning, grouped by origin: the project folder their working directory is in, a browser profile for a chromium and its helpers, else their command. Each group shows its process count, total resident memory and oldest age. Package `proc`.

Instead of: pkill -f and pgrep -f one-liners (which match their own shell), ps aux | grep for leftover chromium, bun or vite processes

```sh
procs
procs  # leftover and heavy dev processes, by origin
procs --min-mem 1G --older 1h  # only the big ones that have run a while
procs --kill  # dry run: what would be stopped
procs --kill --yes
```

## proof

runs the command at HEAD or another ref in a temporary worktree, then in the working tree, to show that a test fails before a change and passes after it. Package `base`.

Instead of: running a test, stashing the change and running it again

```sh
proof [--ref <rev>] [--runs <n>] [--keep <path>...] [--no-link] [--json] -- <command> [args...]
proof --keep tests/fix.test.ts -- bun test tests/fix.test.ts  # the new test fails at HEAD and passes now
proof --ref v1.2.0 --keep tests/fix.test.ts -- bun test tests/fix.test.ts  # the same against a release
```

## redact

copies stdin to stdout line by line with secrets masked: known token formats (GitHub, GitLab, Slack, AWS, npm, Stripe, Google and SendGrid keys, sk-, JWTs, Authorization headers, password= and secret= pairs), private key blocks, the password and the tokens of any URL and the values of secret-looking keys in this folder's .env* files. Package `env`.

Instead of: printing a command's secrets into a log or a transcript

```sh
redact [--check]
docker compose config | redact  # the resolved compose file, secrets masked
git diff --cached | redact --check  # refuse a commit carrying a secret
```

## repos

the git repositories under root (the configured workspace, ~/Workspace by default) that need attention, with their branch, dirty files, ahead/behind their upstream, linked worktrees and commits since their latest tag. Package `workspace`.

Instead of: a cd, git status, git log and git tag loop over each repository of the workspace

```sh
repos [options] [root]
repos
repos ~/Workspace --only unreleased --fetch
repos --only behind --pull  # fast-forward what is behind and clean
repos --only dirty --path  # the paths, for xargs
```

## sf

without a terminal (a script, a pipe, an agent) `sf` lists the commands, one per line with its description: that listing is the form to use there, and `sf --list --json` gives each with its arguments and options. On a terminal it picks a Symfony console command instead and runs it, asking for each required argument it needs. The commands last run come first, per folder, and the picker opens on the list cached from the last run while the console answers. Package `docker`.

Instead of: bin/console typed in the php container, with the command names and arguments looked up by hand

```sh
sf [command] [args...]
sf
sf cache:clear  # run it without the picker
sf c:c --env=prod  # the console resolves abbreviations itself
sf -  # the last command again, with its arguments
```

## slot

waits for a free machine-wide slot, then runs the command and exits with its code. Package `wait`.

Instead of: flock wrappers, hand-written heavy.sh queues and parallel runs fighting over one test database

```sh
slot [options] -- <cmd>...
slot -- bunx vue-tsc  # wait for a free slot, then type-check
slot --lock booki-test-db -- vendor/bin/phpunit  # one phpunit at a time on the shared test database
slot ls
```

## src

reads and ranks the source of a folder: line spans, TODO comments and the files worth splitting. Package `code`.

Instead of: sed -n N,Mp, grep -n chains and grep -rn TODO

```sh
src <command> [options]
src peek src/cli.ts:10-40
src todo-scan
src hotspots -n 10  # the ten files both complex and often edited
```

## stack

a stable port per service name, and a compose release audit. Package `stack`.

Instead of: picking a free host port by hand, and reading compose files against release.config.ts

```sh
stack <command> [options]
stack port api
stack audit  # this folder's release setup
```

## sub

replaces text in files, writing nothing unless every replacement matches as often as expected. Package `edit`.

Instead of: sed -i and one-off bun -e or python editors

```sh
sub [options] <file>...
sub src/a.php <<'EOF' (SEARCH/REPLACE blocks, see above)  # multi-line text, no escaping
sub --from oldName --to newName --all src/a.ts src/b.ts  # every match in two files
sub --regex --from "v(\d+)" --to "v$1.0" --dry-run --diff README.md  # the diff, nothing written
```

## sweep

lists the regenerable folders (node_modules, .output, dist, build, target beside a Cargo.toml), the caches (.nuxt, .next, .turbo, .svelte-kit and node_modules/.cache per project; ~/.bun/install/cache, ~/.npm/_cacache, ~/.cache/{pip,uv,ms-playwright,puppeteer,go-build,typescript} and ~/.cargo/registry, exact paths only, listed only when no root is given or with --only caches) and the .worktrees/* and .claude/worktrees/* entries under root (the configured workspace, ~/Workspace by default, 3 levels down), largest first with the age of the repo's last commit; --only worktrees, folders or caches keeps one kind. Package `workspace`.

Instead of: find ~/Workspace -name node_modules, du -sh and rm -rf by hand

```sh
sweep [options] [root]
sweep
sweep ~/Workspace --older 30d --min 100M --apply
sweep --only worktrees --apply
```

## todo-scan

lists the TODO, FIXME and owner/repo#N comments under the paths (here by default), each as <file>:<line>: <comment>, honouring .gitignore. Package `code`.

Instead of: grep -rn TODO, then opening each issue it names

```sh
todo-scan [options] [path...]
todo-scan src
todo-scan --stale  # only the comments naming a closed issue
```

## view

shows a markdown file, a source file or a git diff in the colours of the other @kaynooo CLIs. Package `view`.

Instead of: cat, bat or less on a markdown file, delta on a diff

```sh
view [options] [file]
view README.md
git diff | view
```

## waitfor

waits until a file shows a line, a port listens, a URL answers 2xx, a process exits or a command exits 0. Package `wait`.

Instead of: sleep loops, tail -f and until ! pgrep -f

```sh
waitfor [options]
waitfor --file dev.log --until "ready in" --fail error  # a dev server up, or its first error
waitfor --port 5432 -t 2m  # Postgres accepting connections
```

## ws

the repositories under a root: the ones needing attention, the folders worth reclaiming and their known vulnerabilities. Package `workspace`.

Instead of: a cd, git status and du loop over each repository of the workspace, and a bun audit run in each

```sh
ws <command> [options]
ws repos
ws sweep --older 30d  # what a month of idle repos weighs
ws audit
```
