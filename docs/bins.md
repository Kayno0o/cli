# Bins

Generated by `bun run docs` from each bin's `--help` description, do not edit.

## arc

packs a folder into a verified .tar.zst before deleting it, unpacks one without overwriting anything and checks it, and extracts any other archive. Package `arc`.

Instead of: tar czf then rm -rf on trust, tar xf over existing files, and remembering which extractor an archive needs

```sh
arc <command> [options]
arc ls backup.tar.zst  # what is in an archive
arc cat backup.tar.zst project/package.json  # one file out of it
arc pack ~/old-project /mnt/backup  # archive, verify, then delete the folder
arc pack -k dist  # compress only: ./dist.tar.zst, the folder stays
arc unpack /mnt/backup/old-project.tar.zst ~/restored  # refuses to overwrite
arc extract release.tar.gz  # any common archive
```

## base

runs a command at HEAD or another ref in a temporary worktree, the working tree untouched. Package `base`.

Instead of: git stash, a test run, then git stash pop

```sh
base <command> [options]
base -- bun test tests/api.test.ts  # the test at HEAD, the working tree changes left out
base proof -- bun test tests/new.test.ts  # it fails at HEAD and passes in the working tree
```

## check

runs the repo's check, typecheck, lint and test steps, from package.json scripts (through bun run), composer.json, a Justfile or a Makefile, and for PHP from phpstan.neon (typecheck), .php-cs-fixer.dist.php (lint, dry-run) and phpunit.xml.dist (test) when composer.json has no such script. Package `check`.

Instead of: chaining docker compose exec <service> bun run check | tail, lint and test by hand, or bun run check && bun run lint && bun run test read through tail, and with --fix each fixer and formatter run by hand

```sh
check [--only <steps>] [--changed] [--failed] [--quiet] [--timeout <duration>] [--slot | --no-slot] [--parallel] [--in <service> | --host] [--list]
check
check --only lint,test  # two of the steps
check --in app  # every step inside the app service
check --fix  # the fixers and formatters instead
check --fix --list  # the fixers it would run
```

## db

read-only SQL against Postgres, MySQL and MariaDB, credentials never shown, writes only on a _test database. Package `db`.

Instead of: psql or mysql with the connection string on the command line, docker exec <container> psql -U ...

```sh
db <command> [options]
db "select count(*) from users"
db -c booki-db-1 "select count(*) from users"  # a container outside the compose project
db describe users  # the columns, indexes and foreign keys of a table
db search email  # where a field lives
db explain "select * from users where email = 'a'"  # the plan, nothing executed
db --format csv "select id, email from users"  # RFC 4180 CSV, or tsv or vertical
```

## dl

downloads a file into a folder of its own, checks its sha256, then extracts it, installs it as a command or runs it as a script once it is pinned. Package `dl`.

Instead of: curl -fsSL <url> | sh, curl -LO then sha256sum -c by hand, and unpacking a release to copy its binary into ~/.local/bin

```sh
dl <command> [options]
dl https://bun.sh/install  # download a script to read it
dl https://bun.sh/install --exec --sha256 <sha>  # run the script that was read
dl https://example.com/tool.tar.gz --sums https://example.com/SHA256SUMS --bin tool  # a checked binary, installed
dl ls  # what dl installed or ran
```

## dlog

one line per compose service with its state and health, then the last distinct error lines of the services that log some or are not healthy, repeats collapsed to one line with a count and secrets masked as redact does. Package `docker`.

Instead of: docker compose ps, logs --tail | grep -i error and docker inspect for health

```sh
dlog [service...]
dlog
dlog php db  # only those services
dlog -n 10 --since 15m  # ten error lines of the last quarter of an hour
dlog --level warn  # warnings too
dlog --grep "timeout|5\d\d"  # the lines matching a regex
dlog --fail-on down --fail-on unhealthy  # a gate that ignores old errors
dlog --json  # the report as JSON
```

## doctor

checks this host's @kaynooo/cli-* install, one line per check, the command that fixes a failing one beside it, and installs the packages it picks. Package `doctor`.

Instead of: checking each bin's version, tea's login and the hooks by hand

```sh
doctor [--only <check>] [--quiet] [--fix | --install [<name>...|all]] [--list] [--dry-run] [--force] [--json]
doctor
doctor --json  # the checks for a script
doctor -q  # silent unless something fails
doctor --fix --dry-run  # what --fix would run
doctor --install  # check to install, uncheck to remove
doctor --install forgejo check hooks  # three named ones
doctor --install all --dry-run  # what installing everything would run
```

## dx

without a terminal (a script, a pipe, an agent) `dx` lists the services with their state, ports and image: that listing is the form to use there, `--json` giving the full record. On a terminal it picks one instead: enter opens its shell (or brings a stopped service up), ctrl-l follows its logs, ctrl-r restarts, ctrl-x stops and ctrl-b rebuilds it. The services last acted on come first, per folder. Package `docker`.

Instead of: docker compose exec <service> bash, logs -f and restart typed per service

```sh
dx [service] [action]
dx
dx php  # a shell in php, or php brought up when stopped
dx php logs  # follow its logs on a terminal, print them once without one
dx php logs --tail 50 --no-follow  # the last 50 lines, then exit
dx -  # the last action again
```

## errs

prints one `file:line:col: message (rule)` line per error found in a tsc, tsgo, vue-tsc, bun check, kay check, eslint, keslint, bun test, vitest, playwright (list and line reporters), phpunit, paratest, phpstan (table, raw and json), php-cs-fixer, go (build, vet), cargo (rustc), ruff (concise and full) or pytest log, or any line shaped `file:line[:col]: error|warning: message` (mypy, gcc, clang, `shellcheck -f gcc`, golangci-lint), read from the file given, from stdin (no argument or -), or from the output of the command run after --. Package `check`.

Instead of: reading raw tsc, eslint, phpunit, phpstan or playwright logs, or grepping a test summary out of them

```sh
errs [options] [log]
errs -- bun run check  # the type errors of a run
bun test 2>&1 | errs  # the failed tests from stdin
errs -- vendor/bin/phpunit  # each failed PHP test with its file and line
```

## gb

without a branch, picks one when a terminal is attached: the branches last checked out first, as the reflog has them, then the other local ones, then the remote ones with no local branch yet. The header says where HEAD stands, each row how its branch stands against its upstream and whether it is merged into the base. enter switches to it (a remote one gets its local tracking branch), ctrl-n creates a branch named after the query, ctrl-d deletes the highlighted local branch with `git branch -d`, which refuses one not merged yet, and ctrl-r fetches, prunes and lists again. Without a terminal it lists the branches instead. Package `git`.

Instead of: git switch, git branch -d and git checkout typed per branch

```sh
gb [branch]
gb
gb feature  # switch to feature, or create it from origin/feature
gb -  # back to the previous branch
gb -c fix/login  # create a branch and switch to it
gb -d old  # delete a merged local branch
```


## gd

what changed in the tracked files, per file with its added and removed lines, then the patch of the paths given. Package `git`.

## gm

merges the branch into the current one with git merge --no-edit, saying what came in. Package `git`.

## gp

pushes the current branch of the repository, or of each dir's, when it is ahead of its upstream as of the last fetch or has none yet, the latter with -u to origin (the only remote when there is no origin). Package `git`.

Instead of: git push, git push -u origin <branch> and a git -C <repo> push per nested repository

```sh
gp [dir]...
gp
gp --repos  # every repository nested in this one
gp --repos --dry-run  # what would go out
gp . ../other  # this repository and a sibling
gp -- --force-with-lease  # flags for git push
```

## gst

the repository's branch, upstream, changed files and HEAD in one line, then the changed paths by staged, unstaged and untracked. Package `git`.

Instead of: git status --short, git log --oneline and a git -C <repo> status per nested repository

```sh
gst [-n N]
gst

gst --repos  # the repositories nested in this one
```

## gu

undoes changes to the paths given, keeping what it takes away. Package `git`.

Instead of: git restore, git restore --staged and git reset --soft HEAD~1 typed blind

## j

without a name, picks a recipe, target, script or task of this folder, its parents and its child folders when a terminal is attached, and runs it. The ones run last come first, per folder. Without a terminal it lists them instead. Package `check`.

Instead of: reading the Justfile, Makefile, package.json scripts or composer scripts to find what to run, then retyping it

```sh
j [name] [args...]
j

j api/test --watch  # a child folder's, with an argument
j just:check  # the one of a runner, when several share the name
j -  # the last one again
```

## pick

a fuzzy selector, the lines on stdin in, the chosen one on stdout out. Package `pick`.

Instead of: fzf for a quick choice in a pipe, select in a shell script

```sh
ls | pick --multi --preview 'head -20 {}'
```


## probe

reports each site's negotiated HTTP version, redirect chain, timings, addresses, TLS and certificate, the headers worth knowing and what warrants a warning. Package `probe`.

Instead of: the httpversion fish function, curl -sI chains, openssl s_client and dig @server one-liners

```sh
probe [options] <url|domain>...
probe example.com
probe https://example.com/path --json
probe a.test b.test  # one line each
probe https://example.com --resolve example.com:203.0.113.7 -H "Host: example.com" --verbose  # a server before its DNS points at it
probe --dns example.com  # whether a DNS change has reached every resolver
probe --cors https://app.example.com --method PUT --cors-headers content-type,authorization https://api.example.com/items  # whether the browser would let the call through
```

## sf

without a terminal (a script, a pipe, an agent) `sf` lists the commands, one per line with its description: that listing is the form to use there, and `sf --list --json` gives each with its arguments and options. On a terminal it picks a Symfony console command instead and runs it, asking for each required argument it needs. The commands last run come first, per folder, and the picker opens on the list cached from the last run while the console answers. Package `docker`.

Instead of: bin/console typed in the php container, with the command names and arguments looked up by hand

```sh
sf [command] [args...]
sf
sf cache:clear  # run it without the picker
sf c:c --env=prod  # the console resolves abbreviations itself
sf -  # the last command again, with its arguments
```

## sub

replaces text in files, writing nothing unless every replacement matches as often as expected. Package `edit`.

Instead of: sed -i and one-off bun -e or python editors

```sh
sub [options] <file>...
sub src/a.php <<'EOF' (SEARCH/REPLACE blocks, see above)  # multi-line text, no escaping
sub --from oldName --to newName --all src/a.ts src/b.ts  # every match in two files
sub --regex --from "v(\d+)" --to "v$1.0" --dry-run --diff README.md  # the diff, nothing written
```

## waitfor

waits until a file shows a line, a port listens, a URL answers 2xx, a process exits or a command exits 0. Package `wait`.

Instead of: sleep loops, tail -f and until ! pgrep -f

```sh

```
