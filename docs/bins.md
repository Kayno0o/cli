# Bins

Generated by `bun run docs` from each bin's `--help` description, do not edit.

## arc

packs a folder into a verified .tar.zst, deleting it only when asked, unpacks one without overwriting anything and checks it, and extracts any other archive. Package `arc`.

Instead of: tar czf then rm -rf on trust, tar xf over existing files, and remembering which extractor an archive needs

```sh
arc <command> [options]
arc ls backup.tar.zst  # what is in an archive
arc cat backup.tar.zst project/package.json  # one file out of it
arc grep TODO backup.tar.zst  # search text inside an archive
arc pack --delete ~/old-project /mnt/backup  # archive, verify, then delete the folder
arc pack dist  # compress only: ./dist.tar.zst, the folder stays
arc extract release.tar.gz  # bomb-proof extract into subfolder when needed
arc extract --verify /mnt/backup/old-project.tar.zst ~/restored  # extract and verify against archive
```

## base

runs a command at HEAD or another ref in a temporary worktree, sharing node_modules and env files with the working tree unless --no-link. Package `base`.

Instead of: git stash, a test run, git bisect, then git stash pop

```sh
base <command> [options]
base -- bun test tests/api.test.ts  # the test at HEAD, the working tree changes left out
base proof -- bun test tests/new.test.ts  # auto-keeps the new test, proves it fails before and passes now
base bisect --good v1.0.0 -- bun test tests/api.test.ts  # find the first commit that broke a test
```

## check

runs the repo's check, typecheck, lint, fmt (fmt:check / format:check) and test steps from package.json (bun/pnpm/yarn/npm), composer.json, deno.json, Justfile, Makefile, Taskfile, mise, pyproject.toml, Go, Rust, Python, or PHP configs, or .checkrc.json; a folder with no steps runs its subfolders and workspaces. Package `check`.

Instead of: chaining docker compose exec <service> bun run check | tail, lint and test by hand, or bun run check && bun run lint && bun run test read through tail, and with --fix each fixer and formatter run by hand

```sh
check [path|workspace...] [--only <steps>] [--changed [--base <ref>]] [--failed] [--fail-fast] [--retry <n>] [--watch] [--quiet] [--timeout <duration>] [--slot | --no-slot] [--lock <name>] [--parallel] [--in <service> | --host] [--list]
check
check packages/kit --only lint,test  # one workspace, two steps
check --changed --base main -x  # narrowed to branch diff, fail fast
check --in app  # every step inside the app service
check --fix --changed  # fixers on changed files only
```

## db

read-only SQL against Postgres, MySQL, MariaDB and SQLite, credentials never shown, writes only on a _test database. Package `db`.

Instead of: psql, mysql or sqlite3 with the connection string on the command line, docker exec <container> psql -U ...

```sh
db <command> [options]
db "select count(*) from users"
db ./app.db "select count(*) from users"  # query a local SQLite file directly
db schema  # compact map of all tables, columns, PKs, and FKs
db describe users  # columns, indexes and foreign keys of a table
db sample users --latest  # newest rows of a table, sensitive columns masked
db explain "select * from users where email = 'a'"  # the plan, nothing executed
```

## dl

downloads a file into a folder of its own, checks its sha256, then extracts it, installs it as a command or runs it as a script once it is pinned. Package `dl`.

Instead of: curl -fsSL <url> | sh, curl -LO then sha256sum -c by hand, and unpacking a release to copy its binary into ~/.local/bin

```sh
dl <command> [options]
dl https://bun.sh/install  # download a script to read it
dl https://bun.sh/install --inspect  # download, inspect script findings and clean up
dl https://bun.sh/install --exec --sha256 <sha>  # run the script that was read
dl https://example.com/tool.tar.gz --sums https://example.com/SHA256SUMS --bin tool  # a checked binary, installed
dl ls  # what dl installed or ran
dl rm tool  # uninstall a tracked binary
dl outdated  # what changed at its source
dl update --dry-run  # preview updates
```

## errs

prints one `file:line:col: message (rule)` line per error found in a tsc, eslint, bun test, vitest, playwright, phpunit, phpstan, php-cs-fixer, go, cargo, ruff or pytest log, or any `file:line[:col]: error|warning: message` line, read from a file, from stdin or from the output of the command run after --. Package `check`.

Instead of: reading raw tsc, eslint, phpunit, phpstan or playwright logs, or grepping a test summary out of them

```sh
errs [options] [log]
errs -- bun run check  # the type errors of a run
bun test 2>&1 | errs  # the failed tests from stdin
errs -- vendor/bin/phpunit  # each failed PHP test with its file and line
```

## gst

## gu
